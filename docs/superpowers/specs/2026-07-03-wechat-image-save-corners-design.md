# 微信长按保存图片圆角兼容性修复设计

## 背景与结论

用户在微信内置浏览器中长按保存生成图后，保存结果的四角出现页面底色形成的圆角。

这不是用户操作错误，而是页面样式与微信保存实现之间的兼容性问题：

- 生成链路通过 Canvas 导出 `image/png`，Canvas 绘制过程没有圆角裁切。
- 页面给可长按保存的 `#result-image` 设置了 `border-radius: 8px`。
- 用户提供的保存结果是 `1146x861` JPEG，不是应用生成的 PNG Blob，并且四角像素接近页面底色 `#fff9ee`。
- 以上证据表明，微信内置浏览器在该场景下保存了图片元素的渲染结果，CSS 圆角随重采样结果写入了文件。

因此，修复点应位于可保存图片元素的展示样式，而不是 Canvas 导出逻辑。

## 目标

- 微信内置浏览器长按保存生成图时，保存结果保持直角，不再混入页面底色圆角。
- 保持现有 PNG 生成、实时更新、取色、文字和版式编辑行为不变。
- 不新增依赖，不引入网络请求，不扩大为下载体系改造。
- 修复完成并验证后推送到 `main`，由现有 GitHub Actions 更新 GitHub Pages。

## 非目标

- 不实现微信 JS-SDK 图片预览或保存接口。
- 不增加 Blob 下载按钮；微信内置浏览器对这类下载链路的处理不一致，且本问题可在样式层直接消除。
- 不修改 Canvas 尺寸、压缩格式或图片内容。
- 不重构页面布局或视觉系统。

## 方案比较

### 方案一：移除结果图片本身的圆角（采用）

将 `.result-panel img` 的圆角明确设为 `0`，保留现有阴影和尺寸约束。

优点：直接消除微信保存渲染结果时的裁切来源；改动最小；不依赖微信 API。

代价：页面上的生成图也显示为直角。

### 方案二：将圆角装饰移动到外层容器

图片本身保持直角，由外层元素提供圆角视觉。

不采用原因：微信若截取整个渲染区域，外层裁切或遮罩仍可能进入保存结果，不能形成可靠保证。

### 方案三：增加显式下载按钮

通过 `<a download>` 或 Blob URL 触发下载。

不采用原因：微信内置浏览器的下载处理并非稳定替代路径，还会增加交互和兼容分支，超出问题所需范围。

## 实现设计

### 样式

在 `styles.css` 的 `.result-panel img` 规则中，将 `border-radius` 从 `8px` 改为 `0`。

保留：

- `max-width`、`max-height` 和 `object-fit`，继续适配手机屏幕。
- `box-shadow`，保留生成图与页面背景的层次。
- `-webkit-touch-callout: default`，继续允许微信长按菜单。
- `background: #fff`，避免图片加载阶段透明区域闪烁。

不在父元素增加 `overflow: hidden`、遮罩或圆角，以免形成新的保存裁切来源。

### 数据流

数据流保持不变：

1. Canvas 完成矩形图像绘制。
2. `canvas.toBlob(..., 'image/png')` 生成 PNG Blob。
3. Blob URL 赋给 `#result-image.src`。
4. 微信内置浏览器展示无圆角的 `<img>`。
5. 用户长按保存时，即使微信保存渲染结果，四角仍包含原图像素。

### 错误处理

本次不改变异步生成和错误提示逻辑。Canvas 导出失败仍使用现有“图片生成失败，请重试”提示。

### 发布

沿用 `.github/workflows/pages.yml` 的现有发布链路，不修改 workflow：

1. 本地测试和浏览器验收通过后提交代码。
2. 将 `main` 推送到 `origin`。
3. GitHub Actions 先执行 `npm test`，通过后部署仓库根目录到 GitHub Pages。
4. 等待本次 workflow 成功，打开 `https://baebear0903.github.io/color-walk-creator/` 验证线上文件和页面行为。

若 Actions 测试或部署失败，先读取失败日志并修复，不把“已推送”等同于“已发布”。

## 测试与验收

### 自动化回归测试

新增一个样式回归测试，读取 `styles.css` 并验证：

- `.result-panel img` 明确声明 `border-radius: 0`。
- 该规则继续允许 `-webkit-touch-callout: default`。

测试必须先在现状下因 `border-radius: 8px` 失败，再修改生产样式使其通过。

### 全量验证

- 运行 `npm test`，确认所有现有和新增测试通过。
- 运行 `git diff --check`，确认无格式错误。
- 启动本地静态服务，以手机视口上传代表性图片并生成结果。
- 检查 `#result-image` 的计算样式为 `border-radius: 0px`。
- 检查生成图四角为直角，取色、文字编辑和重新上传入口仍可用。
- 推送 `main` 后确认 GitHub Pages workflow 成功。
- 使用线上地址重复手机视口检查，确认发布内容不是旧缓存。

微信真机长按保存是最终环境验证。当前本地验证可证明页面不再向微信提供带圆角的渲染源，从根因上消除已观察到的问题。

## 完成标准

- 结果图片元素及其父级不存在会裁切图片四角的圆角或遮罩。
- 新增回归测试完成红—绿验证。
- 全部测试通过，页面在手机尺寸下实际渲染正常。
- GitHub Pages 部署成功，线上结果图计算样式为 `border-radius: 0px`。
- 仅修改本设计涉及的样式、测试和规格文档。
